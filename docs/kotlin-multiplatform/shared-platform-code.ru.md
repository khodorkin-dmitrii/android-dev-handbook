# Общий и платформенный код

В этой статье будет рассмотрено, какие части Kotlin Multiplatform-системы обычно выгодно делать общими, а какие стоит оставлять платформенными. Основное внимание будет уделено явным границам платформ, интеграционным абстракциям и издержкам подхода, при котором команда пытается переиспользовать каждую деталь реализации.

> **Черновик:** Эта статья является структурированной заготовкой и будет расширена в следующей задаче.

## Темы для раскрытия

- Код, который безопасно и полезно делать общим
- Задачи, которые обычно остаются платформенными
- Явные границы платформ
- `expect` и `actual`
- Интерфейсы, адаптеры и dependency injection
- Как избежать ловушки «переиспользовать все»
